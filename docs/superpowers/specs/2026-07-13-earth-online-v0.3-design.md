# Earth Online v0.3 设计规格

日期：2026-07-13  
状态：已与用户确认，等待书面审阅

## 1. 版本目标

v0.3 将 Earth Online 从“好看的清晨面板与成就展示”推进为一个可以每天轻量使用的人生运行系统。

产品的主要价值是：

- 让玩家每天只面对一个真正重要的主线动作。
- 用一个小维护动作保持基本运行，而不是堆叠待办事项。
- 让偶然发生的有意义时刻能留下一句记录。
- 在夜间档案馆中把长期推进沉淀为人生记录、运行记录和个人轨迹。

v0.3 不是任务管理器，不强调连续打卡，不用失败、惩罚或焦虑维持日活。主线约占每日体验的 70%，维护与记录约占 30%。

## 2. 设计原则

### 2.1 轻量，但不静态

- 每天只有三个可操作位：主线行动、今日维护、自由记录。
- 页面通过地球、日夜、状态信号和微动效保持生命感，不通过增加文字说明。
- 不显示长段任务解释，任务标题本身必须足够具体。

### 2.2 记录，而不评判

- 系统记录是否发生，不评判人生进度是快或慢。
- 断签不清空进度，主线暂停不视为失败。
- 敏感成就不由系统自动分类，是否敏感、隐藏或展示完全由玩家决定。

### 2.3 世界观一致

- 清晨面板是白天运行层，负责当下行动。
- 夜间档案馆是夜半球记录层，负责回看和沉淀。
- 两者必须通过真实 3D 地球由昼转夜的过渡连接，不得简化为普通页面跳转。

## 3. v0.3 范围

### 3.1 本版本包含

- 三项每日行动的新清晨面板。
- 唯一活跃主线、主线管理与主线归档。
- 五种运行状态与独立状态图标。
- 根据状态生成的维护建议、每日一次替换、不再推荐和小型自定义池。
- 自由记录和可选的重要标记。
- 三层夜间档案：人生记录、运行记录、个人轨迹。
- 6 项自动运行成就。
- 周聚合轨迹与可选的一句周记。
- 经验幂等赏和编辑幂等。
- IndexedDB 滚动快照和本地恢复界面。
- 现有 v0.2 存档的无损迁移。

### 3.2 本版本不包含

- 云同步、账号、好友、排行榜和真实全服统计。
- 推送提醒、定时催促、音效和连续打卡奖励。
- 完整待办系统、子任务树、截止日期和优先级矩阵。
- AI 自动拆解主线或代替玩家判断人生成就。
- 一次性扩展全部 49 项成就或批量生成全部图标。
- 金币、抽奖、商店和成就兑换。

## 4. 清晨面板

### 4.1 信息层级

清晨面板保留现有清透、低噪音、地球地平线背景。首屏按以下顺序组织：

1. 品牌、时间、运行状态和昼夜切换。
2. 一句早安问候与当前主线。
3. 等级、经验和称号等压缩体征。
4. 主线行动、今日维护、自由记录三个操作位。

“主线行动”占据最大视觉权重。“今日维护”更紧凑。“自由记录”默认只是一个安静的 `+` 入口，点击后原位展开一行输入。

不使用嵌套卡片，不把每个数值放进独立装饰容器。面板通过分隔、对齐、透明度和尺寸建立层级。

### 4.2 主线行动

- 同一时间只能有一条活跃主线。
- 当日主线行动默认继承前一天未完成的行动，玩家可直接修改。
- 正式同步后记录一次当日主线进展，并可立即填写明日下一步。
- 当日继续推进时，可追加多条进展记录，但不再发放经验，也不重复增加“推进天数”。
- 主线可暂停、完成归档、切换或放弃，历史均保留，不显示失败判定。

新建主线只询问两件事：

1. 当前主线是什么。
2. 最小的第一步是什么。

主线管理使用聚焦式覆盖层：背景轻微失焦，只展示当前主线、今日行动、暂停、完成和切换。不在这里增加截止日期、优先级、工时估算或成功标准。

### 4.3 今日维护

今日维护根据当前运行状态从本地任务池中生成。任务必须满足：

- 只包含一个具体动作。
- 通常可在 20 分钟内完成。
- 玩家能够自行明确判断是否完成。
- 不使用“保持积极”“让自己更好”等空泛表述。
- 不做健康、心理或人格诊断。

每个自然日可免费替换一次。被替换的任务当天不再出现，三天内尽量不重复。玩家可将某条标记为“不再推荐”，也可增加少量自定义维护项。这里不做成完整任务编辑器。

状态更改时，若今日维护尚未替换或完成，建议随新状态更新；若玩家已手动替换或完成，则保留当前任务，避免界面悄然改变。

### 4.4 自由记录

- 只记录今天已经发生的一件有意义的小事。
- 每日最多一条，可留空，不形成强制日记。
- 可选一个轻量分类，可选标记为“重要”。
- 重要记录进入个人轨迹；普通记录只参与周聚合。
- 允许修改或删除，不重复发放经验。

## 5. 运行状态

v0.3 只保留五个一眼可辨的状态：

| 状态 | 图标语义 | 识别色 | 维护倾向 |
| --- | --- | --- | --- |
| 稳定运行 | 轨道或脉冲 | 青绿 | 伸展、饮水、简单整理、回复重要消息 |
| 高负载 | 仪表盘 | 琥珀 | 短暂离屏、关闭噪音源、推迟非必要任务 |
| 低能量 | 低电量 | 柔和蓝紫 | 饮水、洗漱、短暂户外、低强度伸展、基础食物 |
| 迷航 | 指南针 | 灰蓝 | 写下最小下一步、删除过期待办、暂停非重要目标 |
| 主线推进 | 向前航线 | 亮青绿 | 移除干扰、准备材料、预留不受打扰的 10 分钟 |

“维护中”并入“低能量”，避免状态过多。状态默认继承前一天，新建档默认为“稳定运行”。更改为可选一键操作，不强制每日填写状态问卷。

状态图标使用统一的 24px 矢量图标体系，优先使用现有开源图标库中的成熟图形，必要时以同等线宽做少量定制。小图标不使用 GPT Image 2 生成位图。颜色只用于识别，不表示状态好坏。

## 6. 经验与等级

| 当日行动 | 首次正式同步经验 |
| --- | ---: |
| 主线行动 | +20 |
| 今日维护 | +8 |
| 自由记录 | +8 |

每日最多获得 36 经验。同一行动的编辑、删除、撤销、恢复和重新同步都不得重复发放经验。奖励通过独立奖励账本记录，而不通过界面当前状态推测。

任务列表不常驻显示 `+EXP`。同步成功时，经验只在操作按钮附近短暂浮现，然后收起。等级和总经验保留在清晨体征中，夜间档案馆不显示经验。

旧存档成就仍参与初始等级估算。新解锁的成就本身不发放经验，避免人生经历被折算成可刷取资源。

## 7. 夜间档案三层结构

### 7.1 人生记录

玩家主动确认的现实人生成就。延续 v0.2 的暖金图鉴、稀有度材质、旧存档扫描和隐私控制。系统不自动验证学历、感情、金钱、家庭或健康经历。

### 7.2 运行记录

由本地行为日志可客观判定的少量系统成就。它们可自动解锁，但只表示 Earth Online 内的使用记录，不对玩家的真实人生下结论。

运行记录使用冷银金属图标、极小青色信号灯和航线、节点、系统符号。它们与人生记录共享近黑背景、正方形图标比例、卡片结构和稀有度逻辑，但必须一眼可区分来源。

### 7.3 个人轨迹

个人轨迹不是成就卡列表，也不使用金属徽章。它是一条深蓝色竖向轨道，小型周节点保持安静，主线归档、成就解锁和重要自由记录等里程碑稍微发亮。

默认不逐条展示每日任务。原始日志留在本地，界面以周聚合。

## 8. 个人轨迹与周归档

周期按设备本地日历的周一至周日计算。新的一周首次打开应用时，上一周自动归档。

周节点聚合：

- 完成的主线正式同步天数。
- 完成的维护数量。
- 自由记录数量。
- 主线启动、暂停、切换、完成或放弃。
- 本周解锁的成就。
- 本周重要自由记录。

系统用简短结构化文案自动生成周摘要，不进行心理分析、人格推断或说教。玩家可选填写“为这一周留一句话”，该文字可编辑、可删除，不发放经验、成就或连续奖励。

每次进入夜间档案馆时，最新且尚未被看过的周节点只进行一次柔和呼吸光，后续保持静止。

## 9. v0.3 运行成就

v0.3 只增加以下 6 项自动成就：

| 成就 | 解锁条件 |
| --- | --- |
| 航线接入 | 首次正式同步主线行动 |
| 稳定推进 | 在 7 个不同本地日期正式同步主线行动 |
| 长期航行 | 在 30 个不同本地日期正式同步主线行动 |
| 维护协议 | 累计正式同步 10 个今日维护 |
| 意外收获 | 累计留下 5 条自由记录 |
| 任务完成 | 首次将一条主线完成归档 |

主线推进按“不同本地日期”计数，同一天的额外进展不重复累加。所有进度均是非连续累积，中断不清零。

只在真正解锁时显示现有 Steam 式成就通知。不使用声音，不弹出预解锁催促，多项同时解锁继续使用队列。

首先使用 GPT Image 2 生成“航线接入”和“任务完成”两枚样本图标。只有在 64px 识别度、冷银材质和与暖金人生记录的区分度通过视觉验收后，才生成剩余 4 枚。

## 10. 数据设计

### 10.1 兼容策略

- 导出文件的 `format` 仍保留 `earth-online-save-v1`，不破坏 v0.2 导入识别。
- 新增数字字段 `schemaVersion: 2`，未带该字段的存档按 v0.2 迁移。
- 所有迁移都在内存中完成和验证后才覆盖当前存档。
- 未知字段和未知成就 ID 继续保留，不在迁移时删除。

旧 `mainQuest` 字符串或简单对象自动迁移为一条活跃主线。旧每日任务和历史继续保留，但不伪造为 v0.3 的主线、维护或自由记录奖励事件。

### 10.2 核心记录

```js
{
  schemaVersion: 2,
  mainQuest: {
    id: "quest-...",
    title: "...",
    status: "active",
    startedAt: "...",
    currentAction: {
      id: "action-...",
      text: "...",
      createdAt: "..."
    }
  },
  mainQuestArchive: [],
  dailyRuns: [
    {
      date: "YYYY-MM-DD",
      status: "stable_operation",
      mainAction: {},
      maintenance: {},
      freeRecord: null
    }
  ],
  activityEvents: [],
  rewardLedger: [],
  weeklyArchive: [],
  maintenancePreferences: {
    excludedIds: [],
    customItems: []
  }
}
```

`activityEvents` 是运行成就、周归档和个人轨迹的事实来源。每个事件至少包含唯一 ID、类型、本地日期、精确时间、相关主线 ID 和最小载荷。统计不从 DOM、通知或当前按钮状态反推。

`rewardLedger` 为每个可获得经验的当日行动保存唯一奖励键，例如 `2026-07-13:main`。经验是已发生的运行记录；事后编辑或删除文本不重复发放，也不因文本修改而反复扣除。

### 10.3 日期语义

所有“今天”、自然日、不同日期成就计数和周一至周日都使用设备本地时区，不使用 `toISOString().slice(0, 10)` 作为本地日期。保存事件时同时记录 ISO 时间戳和生成时的本地日期，避免时区切换后改写历史。

## 11. 本地快照与恢复

### 11.1 存储层级

- `localStorage` 继续保存当前活跃存档，每次有效操作后立即更新。
- IndexedDB 保存滚动快照，不参与日常渲染。
- JSON 导出与导入继续保留，作为跨浏览器和人工备份通道。

### 11.2 快照规则

- 每个本地自然日最多一份日快照，保留最近 14 份。
- 主线完成归档之前生成一份关键快照。
- 导入外部存档并覆盖当前存档之前生成一份关键快照。
- 执行历史恢复之前，先把当前状态生成一份关键快照，因此恢复操作也可被撤回。
- 关键快照保留最近 5 份，与日快照分开计数。

日快照在当天第一次有效修改前复制当前存档，使它实际保存“这一天开始之前”的可恢复状态。

### 11.3 恢复界面与失败处理

- “恢复历史存档”与导入、导出放在同一个低频存档管理区，不占用每日主交互空间。
- 列表显示快照时间、类型和原因，不直接展示存档 JSON。
- 恢复必须经过一次明确确认，成功后重新渲染完整界面。
- 导入文件必须先解析、迁移和验证；任何失败都不得覆盖当前存档。
- IndexedDB 不可用时，主应用继续工作，存档管理区明确显示“历史快照不可用”，不伪装已备份。

## 12. 模块边界

v0.3 在现有纯前端结构内实现，不引入后端或大型框架。核心边界如下：

- **Daily Run**：生成和更新当日三项行动，不直接渲染 UI。
- **Main Quest**：维护唯一活跃主线不变式，处理启动、暂停、切换、完成和归档。
- **Maintenance**：按状态、近三天历史、排除项和自定义池选择建议。
- **Activity Log**：只追加事实事件，向成就、周归档和轨迹提供统一输入。
- **Progression**：根据奖励账本幂等发放经验，不识别界面状态。
- **Achievement Rules**：读取事件日志并只解锁规则明确的运行成就。
- **Weekly Archive**：从日志生成幂等周聚合，保存玩家自写的周记。
- **Snapshot Store**：封装 IndexedDB、保留策略和恢复，不与业务规则耦合。
- **UI Views**：清晨面板、主线覆盖层、夜间三层档案和存档管理区只通过回调收发状态。
- **App Controller**：继续只协调首页、初始建档、白天、昼夜过渡和夜间模式，不承担具体业务计数。

## 13. 交互与可访问性

- 昼夜切换延续 v0.2 的可跳过、可恢复、减少动态效果和单实例保护。
- 状态、昼夜、主线管理和关闭按钮必须有文本提示、键盘焦点和语义化标签。
- 不只依赖颜色识别五种状态，图形和文字同时传达状态。
- 完成、替换和成就通知不得遮挡主线同步按钮。
- 动效不改变布局尺寸，不引起卡片和文字跳动。
- 桌面与手机均保证三项每日行动可完整操作；手机不使用水平滚动承载主流程程。

## 14. 错误处理

- 任何业务写入先生成新存档，验证通过后再替换当前状态。
- 重复点击同步、浏览器重绘和导入重放不得产生重复经验、事件或成就。
- 维护池因排除项过多而无候选时，使用少量安全的通用维护项，不返回空白面板。
- 周归档重复运行时使用周起始日期幂等，不创建重复节点。
- 成就解锁已写入但通知播放失败时，不回滚解锁记录，也不阻塞主界面。
- 快照写入失败不阻塞日常操作，但导入和主线归档前要明确告知“未能创建恢复点”，由玩家决定是否继续高风险操作。

## 15. 验收标准

### 15.1 核心行为

1. 新建与旧存档都只显示三个每日行动位。
2. 同一时间不可能出现两条活跃主线。
3. 主线未完成动作可跨日继承，主线暂停、切换、完成和放弃均保留历史。
4. 维护建议符合当前状态，每日只能免费替换一次，被替换项当天不再出现。
5. 自由记录每天最多一条，可修改、删除和标记重要。
6. 每日经验上限为 36，任何重放路径都不能重复发放。
7. 当天多次主线进展可记录，但只有一次正式奖励和一个进展日计数。

### 15.2 档案与成就

1. 人生记录、运行记录和个人轨迹在无需读取长文字时也可一眼区分。
2. 6 项运行成就均由事件日志幂等解锁，断签不清零。
3. 运行成就不发放经验，不将玩家的运行状态解读为健康或心理结论。
4. 个人轨迹默认按周展示，不铺开每日原始任务。
5. 同一周无论归档逻辑执行多少次，都只有一个周节点。
6. 昼夜切换继续无黑屏、无卡死、可跳过且可返回。

### 15.3 存档安全

1. v0.2 存档导入后的档案、成就、等级、标签和历史均不丢失。
2. 损坏或格式不支持的导入文件不改变当前存档。
3. 任意自然日最多一份日快照，且只保留最近 14 份。
4. 关键快照只保留最近 5 份，且主线完成、导入和恢复均在覆盖前建立恢复点。
5. 恢复任意快照后，恢复前的存档仍可从关键快照中找回。
6. IndexedDB 不可用时，主界面、即时保存和 JSON 导入导出仍可使用。

### 15.4 视觉验收

1. 在桌面与手机视口上，主线位于第一视觉层级，维护和自由记录不与它竞争。
2. 五种状态通过形状和名称可一眼区分，不只靠颜色。
3. 两枚运行成就样本在 64px 下仍可辨识，与人生记录既属于同一档案馆，又不会混淆。
4. 个人轨迹在视觉上是轨道和节点，不是日历、数据看板或另一组嵌套卡片。
5. 所有反馈动画不使内容位移、文字遮挡或操作按钮跳动。

## 16. 实施顺序约束

本文只定义设计，不代替实施计划。后续计划必须按以下风险顺序拆分：

1. 存档模式、本地日期、幂等奖励和 v0.2 迁移。
2. 主线、每日运行和维护核心规则。
3. 清晨面板与状态图标。
4. 事件日志、周归档和三层夜间档案。
5. 运行成就样本图标、解锁规则和通知。
6. IndexedDB 快照、恢复界面和完整回归测试。

任何阶段都不得为了展示未完成的视觉而跳过存档迁移、奖励幂等或日期语义测试。
